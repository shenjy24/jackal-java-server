# 监控部署文档

本文档说明如何使用 `docker-compose-monitoring.yml` 部署 Prometheus、Grafana、node_exporter 和 cAdvisor，用于压测期间观察 Ubuntu 虚拟机和 Docker 容器的 CPU、内存、磁盘 IO、网络和容器 Block IO。

## 目录结构

```text
doc/deploy/monitoring/
├── app.env
├── docker-compose-monitoring.yml
├── prometheus/
│   └── prometheus.yml
├── up.sh
├── down.sh
└── 监控部署文档.md
```

## 组件说明

| 组件 | 作用 | 默认端口 |
| --- | --- | --- |
| Prometheus | 采集、存储、查询指标 | 9090 |
| Grafana | 展示 Prometheus 指标 | 3000 |
| node_exporter | 暴露 Ubuntu 主机 CPU、内存、磁盘、网络指标 | 9100 |
| cAdvisor | 暴露 Docker 容器 CPU、内存、网络、Block IO 指标 | 8081 |

`node_exporter` 和 `cAdvisor` 不是 Prometheus 插件，而是独立 exporter。Prometheus 通过 `prometheus/prometheus.yml` 中的 `scrape_configs` 定时抓取它们暴露的 `/metrics`。

## 配置

配置文件为 `app.env`：

```env
PROMETHEUS_PORT=9090
GRAFANA_PORT=3000
NODE_EXPORTER_PORT=9100
CADVISOR_PORT=8081

GRAFANA_ADMIN_USER=admin
GRAFANA_ADMIN_PASSWORD=admin123

PROMETHEUS_RETENTION_TIME=15d
```

生产或共享压测环境请修改 `GRAFANA_ADMIN_PASSWORD`。

## 启动

监控栈复用项目已有 Docker 外部网络 `rd_net`。如果网络不存在，`up.sh` 会自动创建。

```bash
cd doc/deploy/monitoring
chmod +x up.sh down.sh
./up.sh
```

查看容器：

```bash
docker compose -f docker-compose-monitoring.yml ps
docker ps --filter name=prometheus
docker ps --filter name=grafana
docker ps --filter name=node-exporter
docker ps --filter name=cadvisor
```

## 验证

```bash
curl http://127.0.0.1:9090/-/ready
curl http://127.0.0.1:9100/metrics | head
curl http://127.0.0.1:8081/metrics | head
```

访问地址：

```text
Prometheus: http://服务器IP:9090
Grafana:    http://服务器IP:3000
```

Grafana 默认账号密码：

```text
admin / admin123
```

## Grafana 配置

首次登录 Grafana 后添加 Prometheus 数据源：

```text
Type: Prometheus
URL:  http://prometheus:9090
```

推荐导入 Dashboard：

```text
Node Exporter Full
Docker / cAdvisor container metrics
```

压测时重点观察：

```text
Ubuntu VM CPU 使用率、load、iowait
Ubuntu VM 内存 available、swap
Ubuntu VM 磁盘读写吞吐、await、util
Docker 容器 CPU、内存、网络、Block IO
mysql、iotdb、rd300-server-prod、rd300-web-prod 四个容器的资源曲线
```

## 停止

```bash
cd doc/deploy/monitoring
./down.sh
```

默认不会删除 `prometheus-data` 和 `grafana-data` 数据卷。若确实需要清理历史监控数据，请先确认不再需要压测曲线，再手动删除对应 Docker volume。

## 离线镜像

内网或离线环境需要提前准备以下镜像：

```text
prom/prometheus:v3.13.0
grafana/grafana:13.1.0
prom/node-exporter:v1.11.1
ghcr.io/google/cadvisor:0.60.3
```

在有网络的机器上导出：

```bash
docker pull prom/prometheus:v3.13.0
docker pull grafana/grafana:13.1.0
docker pull prom/node-exporter:v1.11.1
docker pull ghcr.io/google/cadvisor:0.60.3

docker save -o prom-prometheus-3.13.0.tar prom/prometheus:v3.13.0
docker save -o grafana-grafana-13.1.0.tar grafana/grafana:13.1.0
docker save -o prom-node-exporter-1.11.1.tar prom/node-exporter:v1.11.1
docker save -o ghcr-google-cadvisor-0.60.3.tar ghcr.io/google/cadvisor:0.60.3
```

在目标服务器导入：

```bash
docker load -i prom-prometheus-3.13.0.tar
docker load -i grafana-grafana-13.1.0.tar
docker load -i prom-node-exporter-1.11.1.tar
docker load -i ghcr-google-cadvisor-0.60.3.tar
```

## 压测记录建议

每轮压测记录：

```text
压测开始时间和结束时间
设备数、并发连接数、上报频率
TPS、RT、错误率
rd300-server-prod CPU 和内存峰值
mysql CPU、内存、Block IO 峰值
iotdb CPU、内存、Block IO 峰值
Ubuntu VM iowait、磁盘 await、磁盘 util 峰值
```

如果 CPU 不高但 iowait、磁盘 await 或 util 明显升高，优先排查 MySQL/IoTDB 写入、Docker volume 所在磁盘、虚拟机磁盘文件和 Windows 宿主机物理磁盘。
