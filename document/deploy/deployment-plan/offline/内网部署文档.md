# 内网部署文档（服务端）

本文档说明生产服务器无法访问公网时，如何采用“上传部署文件和 jar、内网本机构建镜像、启动容器”的方式部署 `jackal-java-server` 服务端。

本项目包含两个可独立部署的服务：

- `service-admin`：管理后台服务。
- `service-client`：C 端服务。

本目录只负责服务端应用容器部署，不包含 MySQL、IoTDB 等中间件编排和初始化。MySQL、IoTDB 请继续使用 `document/deploy/mysql`、`document/deploy/iotdb` 下已有部署方案。

## 方案概览

内网服务器不需要项目源码、不拉代码、不下载 Maven 依赖，只做以下动作：

1. 首次准备：安装 Docker 和 Docker Compose Plugin。
2. 首次准备：加载固定基础镜像 tar，例如 `eclipse-temurin:21-jre`。
3. 首次准备：确认应用配置中声明的 MySQL、IoTDB 等外部服务已可访问。
4. 每次发布：将新的模块 jar 放到 `deploy/` 目录。
5. 每次发布：用 `deploy/` 目录下的 `Dockerfile` 在内网服务器构建应用镜像。
6. 每次发布：用 `docker compose up -d --no-build app-server` 启动或替换应用容器。

应用部署目录是自包含的：`Dockerfile`、`docker-compose.yml`、`app.env`、脚本和 jar 放在同一个 `deploy/` 目录即可启动应用。

## 默认部署参数

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `ENV` | `prod` | Spring Profile 和镜像 tag 环境前缀 |
| `SPRING_PROFILES_ACTIVE` | `prod` | Spring 激活 profile |
| `SERVICE_CLIENT_PORT` | `18881` | `service-client` 宿主机 HTTP 端口，映射到容器 `8080` |
| `SERVICE_ADMIN_PORT` | `18882` | `service-admin` 宿主机 HTTP 端口，映射到容器 `8080` |
| `APP_LOG_DIR` | `../logs` | 日志根目录，脚本会按模块追加子目录 |
| `APP_MEMORY_LIMIT` | `1G` | 应用容器内存上限 |
| `APP_MEMORY_RESERVATION` | `512M` | 应用容器内存预留 |
| `IMAGE_KEEP_COUNT` | `3` | 每个模块保留的历史应用镜像数量 |
| `RUNTIME_IMAGE` | `eclipse-temurin:21-jre` | 构建应用镜像使用的 Java 运行时基础镜像 |
| `JAR_DIR` | `.` | 上传 jar 目录，默认当前 `deploy` 目录 |

## 基础镜像准备

在可访问 Docker 镜像仓库的机器上准备固定镜像 tar：

```bash
docker pull eclipse-temurin:21-jre
docker save -o eclipse-temurin-21-jre.tar eclipse-temurin:21-jre
```

将镜像 tar 上传到内网服务器：

```text
/data/jackal-java-server/middleware-images/
```

## 内网服务器首次准备

内网服务器需要提前安装：

- Docker Engine
- Docker Compose Plugin
- `tar` / `gzip`

准备部署目录：

```bash
sudo mkdir -p /data/jackal-java-server/deploy /data/jackal-java-server/middleware-images /data/jackal-java-server/logs
sudo chown -R $USER:$USER /data/jackal-java-server
cd /data/jackal-java-server
```

验证 Docker：

```bash
docker --version
docker compose version
```

将 `document/deploy/deployment-plan/offline/` 下的部署文件复制到服务器 `deploy/` 目录，并把构建好的 jar 也放到该目录。上传后至少需要：

```text
deploy/
├── Dockerfile
├── docker-compose.yml
├── app.env
├── up.sh
├── down.sh
├── rollback.sh
├── service-admin-1.0.0-SNAPSHOT.jar
└── service-client-1.0.0-SNAPSHOT.jar
```

## 加载基础镜像

在内网服务器上手动加载已上传的基础镜像 tar：

```bash
docker load -i middleware-images/eclipse-temurin-21-jre.tar
```

验证：

```bash
docker image inspect eclipse-temurin:21-jre
```

## 准备外部服务

应用按 jar 内 `application` 配置连接 MySQL、IoTDB 等外部服务。应用部署目录不包含 MySQL、IoTDB 服务编排和初始化 SQL，内网服务器只需要保证应用配置中的外部服务地址、端口、账号、密码和数据库已经可用。

如果需要部署或初始化 MySQL、IoTDB，请使用现有独立文档：

- `document/deploy/mysql`
- `document/deploy/iotdb`

## 外网构建 jar

在可联网开发机或构建机执行：

```bash
mvn -pl service-admin -am clean package -DskipTests
mvn -pl service-client -am clean package -DskipTests
```

构建产物位于：

```text
service-admin/target/service-admin-1.0.0-SNAPSHOT.jar
service-client/target/service-client-1.0.0-SNAPSHOT.jar
```

将需要发布的 jar 上传到内网服务器：

```text
/data/jackal-java-server/deploy/
```

## 内网构建镜像并启动应用

按需调整应用部署配置：

```bash
vim deploy/app.env
```

常用配置：

```env
ENV=prod
SPRING_PROFILES_ACTIVE=prod
SERVICE_CLIENT_PORT=18881
SERVICE_ADMIN_PORT=18882
APP_LOG_DIR=../logs
APP_MEMORY_LIMIT=1G
APP_MEMORY_RESERVATION=512M
IMAGE_KEEP_COUNT=3
RUNTIME_IMAGE=eclipse-temurin:21-jre
JAR_DIR=.
```

如果 `deploy` 目录下每个模块只有一个匹配 jar，可以直接执行：

```bash
bash deploy/up.sh service-admin
bash deploy/up.sh service-client
```

如果存在多个 jar，显式指定模块 jar：

```bash
bash deploy/up.sh service-admin \
  /data/jackal-java-server/deploy/service-admin-1.0.0-SNAPSHOT.jar

bash deploy/up.sh service-client \
  /data/jackal-java-server/deploy/service-client-1.0.0-SNAPSHOT.jar
```

脚本会：

1. 校验模块名和 jar 文件。
2. 校验 `RUNTIME_IMAGE` 已经存在。
3. 使用内网部署目录下的 `Dockerfile` 构建应用镜像。
4. 写入 `deploy/release-state-<module>`，供排查最近发布状态。
5. 使用 `deploy/docker-compose.yml` 启动或替换应用容器。
6. 保留最近 `IMAGE_KEEP_COUNT` 个 `<module>:prod-*` 镜像，并清理悬空镜像。

镜像 tag 示例：

```text
service-admin:prod-20260608120000
service-client:prod-20260608120500
```

## 发布后检查

查看容器：

```bash
docker ps --filter name=service-admin-prod
docker ps --filter name=service-client-prod
```

查看应用日志：

```bash
docker logs --tail=200 service-admin-prod
docker logs --tail=200 service-client-prod
```

检查 HTTP 端口：

```bash
curl -I http://127.0.0.1:18882
curl -I http://127.0.0.1:18881
```

## 后续发布

每次发布新版本：

1. 外网构建新的模块 jar。
2. 上传新 jar 到 `/data/jackal-java-server/deploy/`。
3. 执行对应模块的 `up.sh` 构建新应用镜像并重启应用。

示例：

```bash
bash deploy/up.sh service-admin \
  /data/jackal-java-server/deploy/service-admin-1.0.0-SNAPSHOT.jar
```

后续应用发布不需要重复加载 JRE 镜像，除非基础镜像版本需要升级。升级基础镜像时，重新上传对应 tar 并执行 `docker load -i`。

## 回滚

查看并选择本机历史镜像：

```bash
bash deploy/rollback.sh service-admin
bash deploy/rollback.sh service-client
```

也可以指定序号或镜像名：

```bash
bash deploy/rollback.sh service-admin 2
bash deploy/rollback.sh service-client service-client:prod-20260608120500
```

回滚只切换应用镜像，不回滚数据库结构和数据。涉及数据库变更的版本上线前，需要提前准备数据库备份和兼容方案。

回滚只能使用本机仍然存在的镜像；`up.sh` 默认每个模块只保留最近 3 个应用镜像。如需更长回滚窗口，请调大 `IMAGE_KEEP_COUNT`。

## 停止

停止并移除指定模块容器：

```bash
bash deploy/down.sh service-admin
bash deploy/down.sh service-client
```

## 常见问题

### up.sh 提示基础镜像不存在

先加载 JRE 基础镜像：

```bash
docker load -i /data/jackal-java-server/middleware-images/eclipse-temurin-21-jre.tar
```

并确认 tag 与 `app.env` 中的 `RUNTIME_IMAGE` 一致：

```bash
docker image inspect eclipse-temurin:21-jre
```

### docker compose 启动时仍尝试构建

确认启动命令使用的是：

```bash
docker compose -f deploy/docker-compose.yml up -d --no-build app-server
```

并确认 `APP_IMAGE` 指向已经构建好的应用镜像。

### 服务连不上 MySQL 或 IoTDB

检查应用对应 profile 的 `application` 配置，以及 MySQL、IoTDB 服务是否已启动并允许应用容器访问。数据库和 IoTDB 的部署与初始化继续按现有独立文档处理。
