# 联网部署文档（多模块）

本文档说明生产环境可访问公网时，如何通过 `deploy` 目录拉取代码、按模块构建镜像、启动服务，以及回滚到本机历史镜像。

本项目为多模块工程，包含两个可独立部署的服务：

- `service-admin`：管理后台服务
- `service-client`：C 端服务

两者共享 `service-core` 库，分别打包为独立可执行 jar、独立容器运行。

## 目录结构

生产服务器上，`deploy` 目录与业务代码目录同级：

```text
部署根目录/
├── deploy/
│   ├── Dockerfile
│   ├── docker-compose.yml
│   ├── deploy.env
│   ├── start.sh
│   └── rollback.sh
└── jackal-java-server/
    └── 业务代码仓库（多模块）
```

脚本通过 `REPO_NAME` 定位业务代码目录，默认路径为 `deploy/../jackal-java-server`。
`docker-compose.yml` 的构建上下文指向业务代码仓库根目录，`Dockerfile` 通过 `MODULE` 构建参数只构建指定模块及其依赖（`mvn -pl <module> -am`）。

## 前置条件

- 服务器已安装 Git、Docker、Docker Compose Plugin，且可访问代码仓库与基础镜像仓库。
- 当前用户可执行 Docker 命令；如未加入 `docker` 组，请使用 `sudo bash` 执行脚本。
- 生产配置 `service-admin/src/main/resources/application-prod.yml`、`service-client/src/main/resources/application-prod.yml` 已按真实环境配置完成。
- 仓库根目录的 `.mvn/settings.xml` 已配置 Maven 公共镜像加速（构建在容器内进行）。

## 首次准备

```bash
mkdir -p deploy && cd deploy
# 放入联网部署文件后，拉取业务代码到同级目录
git clone <代码仓库地址> ../jackal-java-server
chmod +x start.sh rollback.sh
vim deploy.env
```

## 部署配置

`start.sh` 和 `rollback.sh` 默认读取同目录下的 `deploy.env`。

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `ENV` | `prod` | Spring Profile 和镜像 tag 环境前缀 |
| `BRANCH_NAME` | `main` | 部署分支，仅 `start.sh` 使用 |
| `REPO_NAME` | `jackal-java-server` | 业务代码目录名 |
| `SERVICE_CLIENT_PORT` | `18881` | service-client 宿主机端口（映射容器 `8080`） |
| `SERVICE_ADMIN_PORT` | `18882` | service-admin 宿主机端口（映射容器 `8080`） |
| `APP_LOG_DIR` | `../logs` | 日志根目录，脚本会按模块追加子目录，如 `../logs/service-admin` |
| `APP_MEMORY_LIMIT` | `1G` | 容器内存上限 |
| `APP_MEMORY_RESERVATION` | `512M` | 容器内存预留 |
| `IMAGE_KEEP_COUNT` | `3` | 每个模块每次发布后保留的镜像数量 |

每个模块使用独立的镜像名（`<module>`）、容器名与 Compose 项目名（`<module>-<env>`），互不影响。

## 发布

在 `deploy` 目录指定要部署的模块执行：

```bash
bash start.sh service-admin
bash start.sh service-client
```

脚本执行流程：

1. 进入 `../jackal-java-server` 业务代码目录。
2. 拉取远程分支并将本地代码重置到 `origin/${BRANCH_NAME}`。
3. 生成镜像版本，例如 `service-admin:prod-20260605170000-abcdef0`。
4. 创建按模块隔离的日志目录。
5. 使用 `deploy/Dockerfile`（`MODULE=<module>`）只构建该模块及依赖，并启动容器。
6. 保留最近 `IMAGE_KEEP_COUNT` 个 `<module>:${ENV}-*` 镜像，并清理悬空镜像。

## 发布后检查

```bash
docker ps --filter name=service-admin-prod
docker logs -f service-admin-prod
curl -I http://127.0.0.1:18882   # service-admin
curl -I http://127.0.0.1:18881   # service-client
```

## 回滚

查看某模块可用历史镜像：

```bash
docker image ls service-admin --format "{{.Repository}}:{{.Tag}} {{.CreatedSince}}" | grep ":prod-"
```

指定模块与镜像回滚：

```bash
bash rollback.sh service-admin service-admin:prod-20260605170000-abcdef0
```

未指定镜像时，脚本会列出该模块本机可用的 `<module>:${ENV}-*` 镜像：

```bash
bash rollback.sh service-admin
```

## 注意事项

- 回滚只能使用本机仍存在的镜像；默认每个模块只保留最近 3 个生产镜像。
- 回滚只切换应用镜像，不回滚数据库结构和数据；涉及库变更时请提前备份并准备兼容方案。
- `application-prod.yml`、数据库密码、OSS 密钥等敏感配置不要提交到公开仓库。
- `document/deploy/maven/settings.xml` 仅为示例，请勿提交真实私库凭据。
- 生产环境慎用 `docker compose down -v`，该命令会删除相关数据卷。
